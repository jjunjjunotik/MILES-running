# NailSense · AI 손톱 관찰 도우미

사진에 보이는 손톱의 **겉모습**을 정리해 주는 모바일 웹 앱입니다.
AI 비전 모델이 6개 항목을 관찰해 설명하고, 눈에 띈 특징은 그 모습의 의학적 이름과
그런 모습을 만드는 상태들, 위험 신호 점검, 진료 안내까지 정리하며, 기록을 날짜별로
쌓아 변화를 비교해 줍니다.

> **영어와 한국어를 지원합니다.** 기기 언어가 한국어면 한국어, 그 밖에는 영어로 나오고,
> 프로필에서 바꿀 수 있습니다. 화면, 건강 정보 글, 약관, 서버 오류 문구, 분석 결과가 모두 그 언어를 따릅니다.
> 서버 콘솔 로그와 코드 주석은 한국어입니다.

> **이 앱은 의료기기가 아닙니다.** 여러 가능성의 이름을 알려 주지만 어느 하나로
> 확정하지 않으며, 치료를 안내하지 않습니다. 손톱 색소 변화는 눈과 사진만으로 양성과
> 악성을 가릴 수 없습니다. 결과는 안심의 근거가 될 수 없으니, 위험 신호가 하나라도
> 보이거나 변화가 이어진다면 피부과 진료를 받으세요.

## 로그인은 선택입니다

앱을 열면 온보딩만 지나 바로 쓸 수 있습니다. 로그인 화면이 앞을 막지 않습니다.

| | 로그인하지 않았을 때 | 로그인했을 때 |
|---|---|---|
| 분석 | 됩니다 | 됩니다 |
| 결과 저장 | 이 기기 브라우저 안 | 계정 (서버) |
| 사진 저장 | 이 기기 브라우저 안 | 이 기기 브라우저 안 (언제나) |
| 서버에 남는 것 | 없음 | 분석 결과와 기록 |
| 기기를 바꾸면 | 기록이 따라가지 않음 | 기록이 이어짐 |

로그인은 프로필 화면에서 고릅니다. 계정을 만들기 전에 이 기기에 쌓인 기록은 프로필에서
계정으로 가져올 수 있고(중복은 건너뜁니다), 로그아웃하면 로그인 화면으로 쫓겨나지 않고
다시 기기 저장 상태로 돌아갑니다.

### 구글 · 애플 로그인

이메일 외에 구글과 애플 로그인을 붙일 수 있습니다. `.env` 에 자격증명을 넣으면 그때부터
로그인 화면에 버튼이 나타납니다. **넣지 않으면 버튼도, 제3자 스크립트도 나타나지 않습니다.**

- 구글: `GOOGLE_CLIENT_ID` 하나면 됩니다. 브라우저가 받은 ID 토큰을 서버가 구글의 공개키로
  직접 검증합니다(서명 · 발급자 · 수신자 · 만료).
- 애플: 유료 개발자 계정에서 받은 `APPLE_CLIENT_ID` · `APPLE_TEAM_ID` · `APPLE_KEY_ID` ·
  `APPLE_PRIVATE_KEY`(.p8) 가 필요합니다. 인가 코드 교환에 쓰는 client_secret JWT 를
  서버가 그 키로 직접 서명합니다.

**휴대폰 앱**에서는 웹 스크립트 대신 운영체제의 로그인 화면(네이티브)을 씁니다. 구글은 앱 안
웹뷰에서 로그인 창을 막기 때문입니다. 아이폰은 구글 + 애플, 안드로이드는 구글만 보여 줍니다.

- `GOOGLE_IOS_CLIENT_ID`: 아이폰 앱의 구글 로그인 토큰은 iOS 클라이언트 아이디로 나옵니다.
  안드로이드 앱은 웹 클라이언트 아이디(`GOOGLE_CLIENT_ID`)로 나오므로 따로 필요 없습니다.
- `APPLE_BUNDLE_ID`: 아이폰 네이티브 애플 로그인 토큰은 앱 번들 아이디가 수신자입니다.
  이것만 있으면 웹용 애플 설정(Services ID, .p8) 없이도 아이폰 앱의 애플 로그인이 됩니다.

서버는 이 값들만 수신자로 더 받아들일 뿐, 검증(서명 · 발급자 · 만료)은 웹과 똑같이 합니다.

소셜 계정에는 비밀번호가 없습니다. 같은 이메일의 기존 계정에는 **제공자가 확인해 준
이메일일 때만** 연결합니다. 확인되지 않은 이메일로는 연결하지 않습니다. 그러면 남의
이메일을 적어 낸 사람이 그 계정을 가져갈 수 있기 때문입니다.

`npm run check:oauth` 가 이 검증을 실제로 확인합니다. 가짜 제공자를 띄워 정상 토큰은
통과시키고, 수신자가 다르거나 만료됐거나 발급자가 다르거나 남의 키로 서명했거나 본문만
바꿔치기한 토큰은 모두 거절하는 것을 봅니다.

## 계정과 데이터

계정은 이메일과 비밀번호로 만듭니다. 서버는 Node 내장 SQLite 파일 하나를 쓰고, 별도 설치가
필요 없습니다. 첫 기동 때 스키마가 만들어지고, 이후에는 버전이 올라간 마이그레이션만
이어서 적용됩니다. 기존 데이터를 지우거나 컬럼을 떨어뜨리는 마이그레이션은 쓰지 않습니다.
→ `server/db.ts`

| 테이블 | 담는 것 |
|---|---|
| `profiles` | 계정. 이메일, scrypt 비밀번호 해시, 표시 이름 |
| `sessions` | 세션. 토큰 자체가 아니라 토큰의 해시만 |
| `nail_scans` | 분석 시도. 부위, 메모, 상태(`done`/`failed`), 오류 코드, 모델, 사진 참조 |
| `scan_results` | 결과. 사진 품질 · 관찰 · 일반 정보 · 관리 · 상담으로 나눈 다섯 덩어리와 원본 JSON |
| `user_preferences` | 닉네임, 사진 보관 여부, 항목 펼치기, 온보딩 완료 |
| `health_articles` | 건강 정보 글 (앱이 제공하는 콘텐츠) |

**사진은 데이터베이스에 넣지 않습니다.** 분석할 때만 서버를 거쳐 모델로 가고, 끝나면
서버 어디에도 남지 않습니다. 사진은 촬영한 기기의 브라우저(IndexedDB)에만 저장되며,
`nail_scans.image_ref` 에는 그 사진을 찾는 키만 남습니다. 같은 기기를 여러 사람이 쓸 수
있으므로 사진 키에는 사용자 아이디가 붙습니다.

### 남의 기록은 열리지 않습니다

- 사용자 데이터를 읽고 쓰는 **모든 질의에 `WHERE user_id = ?` 가 붙습니다.** 아이디를
  알아도 남의 기록에는 닿지 못하고, 남의 기록과 없는 기록은 똑같이 404 입니다.
- 비밀번호는 scrypt 해시와 사용자별 솔트로만 저장하고, 비교는 `timingSafeEqual` 로 합니다.
- 세션 토큰은 httpOnly · SameSite=strict 쿠키에만 있고 **서버에는 해시만** 둡니다.
  데이터베이스 파일이 새어도 그것만으로 남의 세션을 흉내 낼 수 없습니다.
- 상태를 바꾸는 모든 요청은 같은 출처에서 온 것만 받습니다(쿠키 인증 + CSRF 방지).
- 로그인 실패 메시지는 계정이 있든 없든 같은 문장이라, 가입 여부가 새지 않습니다.
- 오류 로그에는 사진도, 요청 본문도, 이메일도 남기지 않습니다.

## 특이 사항: 이름과 위험 신호까지

사진에서 눈에 띈 특징은 따로 떼어내 여섯 조각으로 보여 줍니다. "결이 보입니다"에서
멈추면 쓸 데가 없고, "흑색종입니다"라고 단정하면 사진으로 할 수 없는 말을 하는 것이기
때문입니다. → `shared/analysis.ts`, `web/src/components/FindingList.tsx`

| 조각 | 담는 내용 |
|---|---|
| 무엇이 보이는지 | 어디에, 폭은 얼마나, 색조가 고른지 (`label`, `detail`) |
| 이 모습의 이름 | 예: `조갑 흑색선조(melanonychia striata)`, `보우선(Beau's line)` (`patternNames`) |
| 이런 모습을 만드는 상태들 | 실제 이름으로 2~5개. 각각 `likelihood` 를 답니다 (`possibilities`) |
| 위험 신호 점검 | 교과서적인 신호를 하나씩 `보임` / `보이지 않음` / `확인 어려움` (`signChecks`) |
| 사진으로 가릴 수 없는 것 | 무엇을 못 가리는지 + 진료실에서는 무엇으로 확인하는지 (`cannotTell`) |
| 무엇을 하면 되는지 | 어느 과에 언제, 진료 때 무엇을 요청·준비할지 (`nextSteps`, `watchFor`, `timeframe`) |

### 이름은 말하고, 확정은 하지 않습니다

이름을 감추면 사용자가 스스로 찾아볼 수도, 진료 때 물어볼 수도 없습니다. 그래서
`손발톱 흑색종(subungual melanoma)`, `조갑진균증` 같은 이름을 그대로 적습니다.
다만 **목록**으로 적고 각각에 `likely` / `possible` / `uncommon` /
`rare_important` 를 답니다. 사진 한 장으로는 색소가 손톱판 안에 있는지 아래에
있는지도 가릴 수 없고, 양성과 악성은 더모스코피와 조직검사로 가리는 것이기 때문입니다.

### 놓치는 쪽의 실수를 더 무겁게 봅니다

이 앱이 저지를 수 있는 최악은 흑색종을 "괜찮아 보인다"로 넘기는 것입니다. 그래서:

- **확인되지 않은 것은 `absent` 가 아니라 `unclear` 입니다.** 모델이 모르는 값을
  보내도 서버가 `unclear` 로 떨어뜨립니다.
- **단계는 코드에서 한 번 더 올립니다.** 위험 신호가 하나라도 `보임`이면 모델이
  뭐라고 했든 `soon`, 놓치면 안 되는 가능성이 걸려 있는데 신호가 `확인 어려움`으로
  남으면 최소 `consult` 입니다. 올리기만 하고 내리지 않습니다. → `server/analysis-core.ts`
- **안심시키는 말을 금지합니다.** "정상입니다", "걱정하지 않으셔도 됩니다",
  "양성으로 보입니다"는 프롬프트에서 막습니다. → `server/prompt.ts`
- `soon` 이 하나라도 있으면 결과 화면 맨 위에 진료 안내가 먼저 뜹니다.

### 치료는 안내하지 않습니다

`nextSteps` 는 "어느 과에 언제 가서 무엇을 요청할지"와 "자극을 줄이는 일반 관리"까지입니다.
약 이름, 용량, 연고, 시술, 집에서 하는 처치는 프롬프트와 스키마 설명 양쪽에서 금지합니다.

## 사진 품질 사전 확인

보내기 전에 이 기기에서 먼저 봅니다. 가운데 영역의 평균 밝기와, 이웃 픽셀의 밝기 차이로
잰 선명도를 봅니다. 너무 어둡거나 하얗게 날아갔거나 초점이 흐려 보이면 다시 찍기를
권하는 안내가 뜹니다. 다만 **막지는 않습니다.** 기준이 정확한 측정이 아니라서, 판단은
사용자에게 맡기고 "분석은 할 수 있지만 볼 수 있는 항목이 줄어들 수 있다"는 안내만
띄웁니다. → `web/src/lib/image.ts`

## 분석이 막혔을 때

서버가 잠깐 막히거나 모델이 혼잡할 때 사용자를 오류 화면으로 내보내지 않습니다.
분석 화면을 그대로 둔 채 2초에서 15초까지 간격을 늘려 가며 **될 때까지 다시 시도**하고,
서버가 `Retry-After` 를 주면 그만큼 기다립니다. 빠져나갈 길은 화면의 **Stop** 버튼입니다.
→ `web/src/screens/ScanScreen.tsx`

두 번째 시도부터는 "We're still trying, so you can leave it running"과 시도 횟수를 조용히 덧붙이고,
네 번을 넘기면 마지막 서버 응답을 참고 정보로 함께 보여 줍니다. 설정이 잘못돼 있으면
(모델 이름 오타 같은) 그 문장이 단서가 됩니다.

다시 보내도 답이 달라지지 않는 것만 바로 알려 줍니다. 손톱이 보이지 않는 사진,
너무 흐린 사진, 보낼 수 없는 파일이 여기 해당합니다. 이건 실패가 아니라 "다시 찍어 주세요"라는
결과라서 붙잡아 둘 이유가 없습니다.

## 확정하지 않도록 만든 방법

안전 문구를 덧붙이는 데 그치지 않고, 구조에서부터 확정이 나올 자리를 없앴습니다.

- **"진단" 칸이 없습니다.** 스키마에는 상태의 *목록*만 있고, 그중 하나를 고르는
  필드도 치료 필드도 존재하지 않습니다. → `shared/analysis.ts`, `server/schema.ts`
- **하나로 좁히지 않습니다.** `possibilities` 는 언제나 배열이고, 각 항목에
  `likelihood` 가 붙습니다. 화면에서도 `cannotTell`("사진만으로는 이 중 어느 쪽인지
  가릴 수 없어요")을 상태 목록에서 떼어 놓지 않습니다.
  → `web/src/components/FindingList.tsx`
- **상태값은 중증도가 아닙니다.** `good` / `watch` / `consult` 는
  "얼마나 신경 써서 지켜볼 만한가"를 뜻하며, `consult` 는
  "사진만으로는 판단이 어려우니 직접 보여 주는 편이 낫다"는 의미입니다.
- **시스템 프롬프트가 확정·치료 안내·안심시키는 말·겁주는 말을 모두 금지합니다.**
  → `server/prompt.ts`
- **관찰 지표(0~100)는 건강 점수가 아닙니다.** 같은 환경에서 찍은 사진끼리
  변화를 비교하기 위한 참고 수치라고 화면마다 명시합니다.
- **팁은 누구에게나 무해한 생활 습관 수준으로 제한합니다.**
  영양제 용량, 약물, 시술은 프롬프트와 스키마 설명 양쪽에서 금지합니다.
- **손톱이 아니거나 관찰이 어려운 사진은 결과를 만들지 않고 다시 찍도록 안내합니다.**

## API 키를 안전하게 다루기

키는 **서버 프로세스의 환경변수로만** 존재해야 합니다. 이 저장소는 키가 새는
네 가지 경로를 각각 막아 두었습니다.

| 새는 경로 | 막는 장치 |
|---|---|
| 클라이언트 번들에 섞여 들어감 | `npm run check:secrets` 가 `dist/`·`demo/` 를 훑고, 빌드가 이를 자동 실행해 실패시킵니다 (Anthropic `sk-ant-`, Google `AIza` 등) |
| git 에 커밋됨 | `.gitignore` 가 `.env*` 를 제외하고, `.githooks/pre-commit` 이 커밋 전에 검사합니다 |
| 로그·오류 응답에 찍힘 | 서버는 요청 본문을 로깅하지 않고, 로그로 나가는 문자열은 `redact()` 를 거칩니다 |
| 엔드포인트가 공개되어 남이 대신 씀 | `/api/analyze` 에 같은 출처 검사와 IP별·전체 속도 제한이 걸려 있습니다 |

**Vite 를 쓸 때 가장 흔한 사고**는 키 이름을 `VITE_` 로 시작하게 짓는 것입니다.
그 순간 키가 클라이언트 번들에 그대로 새겨져 브라우저를 여는 누구나 볼 수 있습니다.
서버는 기동할 때 이런 이름을 발견하면 경고하고, 검사기는 빌드를 실패시킵니다.

### 키 넣기

```bash
echo 'GEMINI_API_KEY=발급받은_키' > .env   # 또는 ANTHROPIC_API_KEY
chmod 600 .env                       # 본인만 읽도록
git config core.hooksPath .githooks  # 커밋 전 자격증명 검사 켜기 (권장)
npm run dev
```

#### 설정할 수 있는 값

필수는 분석 키 하나이고, 나머지는 모두 기본값이 있어 비워 둬도 됩니다.

| 이름 | 기본값 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` / `ANTHROPIC_API_KEY` | 없음 | 분석 키. 없으면 샘플 결과로 동작(데모) |
| `ANALYSIS_PROVIDER` | 자동 | `gemini` 또는 `claude`. 둘 다 있으면 Gemini |
| `GEMINI_MODEL` / `ANTHROPIC_MODEL` | 아래 표 | 404 가 나면 `npm run models` 로 목록 확인 |
| `PORT` | `8787` | 서버 포트 |
| `DATA_DIR` / `DB_FILE` | `./data`, `./data/nailsense.db` | 데이터베이스 위치(백업 대상) |
| `GOOGLE_CLIENT_ID` | 없음 | 구글 로그인(선택) |
| `APPLE_CLIENT_ID` · `APPLE_TEAM_ID` · `APPLE_KEY_ID` · `APPLE_PRIVATE_KEY` | 없음 | 애플 로그인(선택). `.p8` 내용은 한 줄로, 줄바꿈 자리에 `\n` |
| `ALLOW_DEMO_FALLBACK` | `true` | 공개 배포 때는 `false` 권장 |
| `RATE_LIMIT_PER_IP` · `RATE_LIMIT_GLOBAL` · `RATE_LIMIT_WINDOW_MS` | `12` · `240` · `300000` | 분석 요청 속도 제한 |
| `AUTH_RATE_LIMIT_PER_IP` · `AUTH_RATE_LIMIT_GLOBAL` · `AUTH_RATE_LIMIT_WINDOW_MS` | `20` · `200` · `600000` | 로그인·가입 속도 제한 |
| `ALLOWED_ORIGINS` | 같은 출처만 | 다른 도메인에서 서빙할 때 쉼표로 나열 |
| `TRUST_PROXY` | `false` | 리버스 프록시 뒤에서만 `true` |

`.env` 는 서버가 기동할 때 Node 내장 `process.loadEnvFile` 로 읽습니다.
이미 설정된 환경변수는 덮어쓰지 않으므로, 배포 환경에서는 `.env` 없이
환경변수만 주입해도 됩니다.

키를 터미널 명령에 직접 쓰면 셸 히스토리에 남습니다. `.env` 파일에 넣으세요.

기동하면 서버가 키 상태를 점검해 `.env` 권한, 값에 섞인 공백, `VITE_` 접두사
문제를 알려 줍니다. **키 값이나 그 일부는 로그에 절대 출력되지 않습니다.**

### 공개된 곳에 배포한다면

- `ALLOW_DEMO_FALLBACK=false` 로 두어 키 누락을 조용히 넘기지 않게 하세요.
- 속도 제한은 프로세스 메모리에만 있습니다. 여러 대로 띄우거나 실제 트래픽을
  받는다면 앞단(리버스 프록시, API 게이트웨이)에 제대로 된 제한을 두세요.
- 리버스 프록시 뒤에서만 `TRUST_PROXY=true` 를 켜세요. 프록시가 없는데 켜면
  누구나 `X-Forwarded-For` 를 위조해 속도 제한을 우회할 수 있습니다.
- 불특정 다수에게 연다면 속도 제한만으로는 부족합니다. 로그인이나 접근 토큰을
  앞단에 두어 호출할 수 있는 사람을 제한하세요.

### 키가 노출됐다면

지우는 것으로는 부족합니다. 커밋 이력, 캐시, 포크, 로그 어딘가에 남습니다.
[console.anthropic.com](https://console.anthropic.com/settings/keys) 에서
**해당 키를 폐기(revoke)하고 새로 발급**하세요. 그다음에 흔적을 정리하면 됩니다.

## 사진과 개인정보

- 로그인은 선택입니다. 로그인하지 않으면 분석 기록과 사진은 **브라우저의 IndexedDB**에만
  저장되고, 로그인하면 분석 결과만 계정(서버)에 저장됩니다. 사진은 어느 경우든 기기에만 남습니다.
- 업로드 전에 캔버스로 재인코딩해 **EXIF 메타데이터(촬영 위치·기기·시각)를 제거**하고,
  긴 변을 1280px 이하로 줄입니다. → `web/src/lib/image.ts`
- API 키는 **서버 환경변수에만** 두고 브라우저로 내려보내지 않습니다.
  브라우저는 자체 서버의 `/api/analyze` 만 호출합니다.
- 서버는 요청 본문을 로깅하지 않습니다. 오류 시에도 오류 코드만 남깁니다.
- 공유 카드에는 손톱 사진이 들어가지 않고 요약만 담깁니다.
- 프로필 화면에서 사진만 또는 전체 기록을 한 번에 삭제할 수 있고,
  "Save analyzed photos"를 끄면 결과만 남고 사진은 저장되지 않습니다.

## 언어 (영어 · 한국어)

- **정하는 법**: 프로필에서 고른 언어 → 없으면 기기(브라우저) 언어. 한국어 기기면 한국어, 나머지는 영어.
  바꾸면 페이지를 다시 불러와 프로필로 돌아옵니다. (`web/src/i18n.ts`)
- **화면 문구**: 코드에서 `L("영어", "한국어")` 로 함께 적습니다. 라벨 묶음은 `web/src/labels.ts`.
- **서버**: 화면은 모든 요청에 `X-NailSense-Locale` 헤더를 실어 보내고, 서버는 오류 문구를 응답 직전에
  한 곳(`server/i18n.ts`)에서 바꿉니다. 새 오류 문구를 만들면 그 표에 한국어를 더합니다.
- **분석 결과**: 요청 언어를 프롬프트에 넣어 모델이 그 언어로 답합니다(한국어는 존댓말, 범위는 "3~4줄").
- **건강 정보 글**: 같은 글이 두 언어로 있고(`shared/articles.ts`), 서버 표는 `(slug, 언어)` 로 나뉩니다.
- **글꼴**: 라틴은 IBM Plex Sans, 한글은 IBM Plex Sans KR. 한글 글꼴은 화면에 한글이 나올 때 그 글자 조각만 받습니다.
- **동의**: 한국어 화면은 개인정보보호법에 맞춰 **민감정보(건강 정보) 처리**와 **국외 이전(미국 서버·AI 업체)**을
  각각 받고, 받는 곳·국가·항목·보유 기간·거부 방법을 함께 보여 줍니다.
- **약관**: 영어와 한국어 초안이 따로 있습니다(`shared/legal.ts`). 한국어 방침에는 개인정보 보호책임자,
  국외 이전, 위탁, 파기, 권익침해 구제 항목이 들어 있고, 채워야 할 곳은 `[…]` 로 표시되어 있습니다.

## 유료 구독 (App Store · Google Play 인앱 구독)

Pro 는 **휴대폰 앱의 인앱 구독**으로만 팝니다(App Store · Google Play 결제). 앱 안의 디지털 구독은
스토어 규정상 스토어 결제를 써야 하므로 웹 결제는 두지 않습니다. 스토어 영수증 확인은
[RevenueCat](https://www.revenuecat.com) 이 맡습니다. 카드 정보는 애플·구글만 갖고, 이 서버로 오지 않습니다.

**아래 값을 넣기 전까지는 꺼져 있습니다.** 이때는 요금제 화면이 보이지 않고 분석 횟수 한도도 없습니다.

| 요금제 | 할 수 있는 것 |
|---|---|
| Free | 한 달에 3번 분석 (`FREE_SCANS_PER_MONTH`), 결과 전체 |
| Pro | 하루 20번까지 분석 (`PRO_SCANS_PER_DAY`), 결과 전체 |

- **안전 정보는 요금제와 상관없이 모두 보입니다.** 위험 신호 점검, 진료 안내, 지난 결과는
  한도를 다 써도 그대로 볼 수 있습니다. 요금제가 바꾸는 것은 새로 분석할 수 있는 횟수뿐입니다.
- 로그인하지 않은 손님은 기기(웹은 쿠키, 앱은 설치 때 만든 무작위 아이디)와 IP 를 함께 세어
  (`GUEST_SCANS_PER_IP_PER_MONTH`, 기본 15) 앱을 다시 깔아도 한도가 새로 차지 않게 합니다.
- 가격과 무료 체험은 코드가 아니라 **스토어에 설정한 값**을 앱이 현지 통화로 그대로 보여 줍니다.

| 환경변수 | 어디서 | 성격 |
|---|---|---|
| `REVENUECAT_SECRET_KEY` | RevenueCat › Project settings › API keys › Secret API key (`sk_…`, v1) | **비밀**. 서버에만 |
| `REVENUECAT_WEBHOOK_AUTH` | 직접 만든 긴 무작위 문자열(16자 이상). 대시보드 웹훅의 Authorization 값과 같게 | **비밀** |
| `REVENUECAT_IOS_KEY` | App Store 앱의 Public API key (`appl_…`) | 공개 |
| `REVENUECAT_ANDROID_KEY` | Play Store 앱의 Public API key (`goog_…`) | 공개 |
| `REVENUECAT_ENTITLEMENT` | 권한(Entitlement) 이름. 기본 `pro` | 공개 |

**믿는 순서**: 앱이 "샀다"고 해도 Pro 를 켜지 않습니다. 앱은 구매 뒤 서버에 확인(`POST /api/billing/sync`)만
부탁하고, 서버가 RevenueCat 에 직접 물어본 결과로 Pro 를 켭니다. 웹훅(`POST /api/billing/store-webhook`)도
"이 계정이 바뀌었다"는 신호로만 쓰고 상태는 다시 물어 저장하므로, 웹훅 본문을 꾸며도 Pro 가 생기지 않습니다.

- 구매는 **로그인한 계정**에 붙습니다(RevenueCat 사용자 아이디 = NailSense 계정 아이디).
  다른 기기나 재설치 뒤에는 로그인하고 **구매 복원**을 누릅니다. 다른 계정으로 복원하면 Pro 가 그 계정으로 옮겨 갑니다.
- 해지·결제 수단 변경은 **스토어에서** 합니다. 앱의 "구독 관리·해지"가 그 기기의 스토어 구독 화면을 엽니다.
  아이폰에서 산 구독을 안드로이드 앱에서 보면(또는 반대) 구독한 기기의 스토어에서 관리하라고 안내합니다.
- **계정을 지워도 스토어 구독은 해지되지 않습니다.** 삭제 화면에서 이 사실을 먼저 알리고,
  서버는 RevenueCat 쪽 고객 기록 삭제만 요청합니다.
- 심사용 sandbox 구매도 Pro 로 인정합니다(App Store 심사는 sandbox 로 결제해 봅니다).
- **웹사이트**(서버가 함께 내주는 화면)에는 결제 버튼이 없습니다. 요금제 화면은 지금 요금제와 남은 횟수,
  "앱에서 구독하세요" 안내만 보여 줍니다. 앱에서 구독한 계정으로 웹에 로그인하면 웹에서도 Pro 입니다.

### 설정 순서

1. RevenueCat 프로젝트를 만들고 App Store 앱 · Play Store 앱을 추가합니다(앱 아이디 확정 후).
2. 각 스토어에 구독 상품 두 개(월간·연간)를 만들고, RevenueCat 에서
   Entitlement `pro` 에 붙인 뒤 Offering(current)의 Monthly · Annual 패키지로 넣습니다.
   **상품 아이디에 `monthly` · `yearly` 를 넣으면** 서버가 기간을 알아봅니다.
3. RevenueCat › Integrations › Webhooks: 주소 `https://<서버>/api/billing/store-webhook`,
   Authorization 에 `REVENUECAT_WEBHOOK_AUTH` 와 같은 값.
4. `fly secrets set REVENUECAT_SECRET_KEY=… REVENUECAT_WEBHOOK_AUTH=… REVENUECAT_IOS_KEY=… REVENUECAT_ANDROID_KEY=…`

```bash
npm run check:store                    # 서버: 동의, 무료 한도(웹·앱 손님, 계정), Pro 하루 한도, 구매 확인,
                                       #   웹훅 인증·중복·재시도, 체험·해지 예약·결제 문제·환불, 계정 간 이전,
                                       #   만료 뒤 재확인, 계정 삭제, 웹 결제 경로가 없어졌는지
npm run build && npm run e2e:store     # 화면: 한도 안내 → 요금제 → 로그인 → 가격·체험·자동 갱신 안내 → 구매 → Pro
                                       #   → 스토어 구독 관리 → 동의 철회 → 구독 중 계정 삭제 → 복원, 웹엔 결제 버튼 없음
```

진짜 스토어 결제 창은 실제 기기와 스토어 테스트 계정에서만 열 수 있어, 위 점검은 결제 단계만 가짜로 바꿔 돌립니다.

> 예전에 붙였던 웹 결제(Paddle)는 없앴습니다. `.env` 나 서버 비밀값에 `PADDLE_` 로 시작하는 값이 남아 있으면
> 서버가 기동할 때 이름만 알려 줍니다(값은 찍지 않음). 지우고, Paddle sandbox 의 API 키도 폐기해 두세요.

## 동의와 약관

- **첫 분석 전에 건강 데이터 처리 동의**를 받습니다. 미리 체크해 두지 않고, 사진이 어디로 가고
  무엇이 남는지 먼저 보여 준 뒤 사용자가 직접 체크해야 분석이 됩니다. 서버도 동의 버전
  (`shared/billing.ts` 의 `HEALTH_CONSENT_VERSION`) 표시가 없는 분석 요청은 거절합니다.
  로그인했으면 동의 시각과 문구 버전을 계정에 남기고, Profile 에서 언제든 거둘 수 있습니다.
  동의 문구를 바꾸면 버전을 올려 모두에게 다시 묻게 합니다.
- **구독 전에는** 현지 통화 가격, 갱신 주기, 체험이 끝나면 청구된다는 것, 24시간 전까지 해지하지 않으면
  자동 갱신된다는 것과 해지 방법을 구독 버튼 가까이에 적습니다. 실제 결제 확인은 스토어의 결제 창에서 합니다.
- 개인정보처리방침과 이용약관은 `shared/legal.ts` 에 있는 **영어 · 한국어 초안**입니다.
  변호사 검토 전이라 화면에 "Draft for legal review" 표시가 붙습니다. 검토가 끝나면 문구를 고치고,
  `OPERATOR` 의 빈칸(운영자 이름·주소·연락처·준거법·EU/영국 대리인)을 채우고,
  `LEGAL_STATUS` 를 `"final"` 로 바꿉니다. 초안 안의 `[…]` 표시는 확인이 필요한 곳입니다.
- 서버 없는 단일 HTML 데모는 사진이 기기를 떠나지 않으므로 동의 창과 요금제를 보여 주지 않습니다.

### 아직 하지 않은 것

- 실제 스토어 결제(sandbox · 테스트 계정 포함)로 구매해 본 적은 없습니다. 가짜 RevenueCat 서버와 가짜 스토어
  플러그인으로 전 과정을 확인했습니다. 실제 기기에서 스토어 테스트 계정으로 한 번 사 보세요.
- 무료 체험을 몇 번 받을 수 있는지는 스토어가 정합니다(같은 Apple 계정 · Google 계정에는 보통 한 번).
- 손님으로 쓰던 무료 횟수는 가입하면 계정 기준으로 새로 셉니다.
- Pro 전용 기능은 아직 "더 많은 분석 횟수" 하나뿐입니다(사진 나란히 비교, 재촬영 알림, 진료용 PDF 등은 없음).
- 약관·개인정보처리방침은 법률 검토 전 초안입니다. 의료기기 해당 여부도 출시 전에 전문가 검토가 필요합니다.

## 배포 (Fly.io)

서버는 **미국 서부(산호세) 한 곳**에 둡니다. 분석 한 번이 10~30초라 한국에서 미국 서버까지의
왕복 시간(약 0.2초)은 체감되지 않고, 이름에 해시가 붙은 화면 파일(`/assets/…`)은 1년 캐시를 걸어
브라우저와 앞단 CDN 이 가까운 곳에서 다시 씁니다. 데이터베이스가 파일 하나(SQLite)라서
**서버는 한 대만** 둡니다(`--ha=false`).

### 처음 한 번

```bash
# 1. Fly CLI 설치와 로그인 (https://fly.io/docs/flyctl/install/)
fly auth signup            # 또는 fly auth login

# 2. fly.toml 의 app 이름을 남과 겹치지 않게 바꾼 뒤 앱 만들기
fly apps create <앱이름>

# 3. 데이터베이스를 둘 저장공간(볼륨) 만들기. 1GB 면 충분합니다.
fly volumes create nailsense_data --region sjc --size 1

# 4. 비밀값 넣기 (.env 에 있던 값들. 값이 터미널 기록에 남지 않게 주의)
fly secrets set GEMINI_API_KEY=… REVENUECAT_SECRET_KEY=… REVENUECAT_WEBHOOK_AUTH=… \
  REVENUECAT_IOS_KEY=… REVENUECAT_ANDROID_KEY=…

# 5. 배포 (서버 한 대)
fly deploy --ha=false
```

배포가 끝나면 `https://<앱이름>.fly.dev` 로 열립니다. 이후에는 `fly deploy --ha=false` 만 다시 하면 됩니다.

### 배포한 뒤 바꿀 것

- **RevenueCat 웹훅 주소**: `https://<앱이름>.fly.dev/api/billing/store-webhook` (위 "유료 구독" › 설정 순서 3).
- 앱 빌드의 API 주소: `APP_API_BASE=https://<앱이름>.fly.dev npm run build:app` 뒤 `npx cap sync`.
- **구글·애플 로그인**을 쓴다면 각 콘솔에 새 주소를 허용 출처로 추가합니다.

### 운영할 때

- **백업**: Fly 는 볼륨 스냅샷을 매일 자동으로 찍어 며칠 보관합니다(`fly volumes snapshots list`).
- **로그**: `fly logs`. 서버는 사진이나 요청 본문을 로그에 남기지 않습니다.
- **서버 한 대 확인**: `fly scale count 1`. 두 대가 되면 데이터베이스가 둘로 갈라집니다.
- **도메인**: 스토어에 올릴 개인정보처리방침 · 지원 주소는 `fly.dev` 주소로도 됩니다. 나중에 도메인을 사면
  `fly certs add <도메인>` 으로 연결하고, 스토어 등록 정보와 앱 빌드의 `APP_API_BASE` 를 함께 바꿉니다.
  이때 Cloudflare 같은 CDN 을 도메인 앞에 두면 공개 페이지가 한국에서도 가까운 곳에서 나갑니다.

## 휴대폰 앱 (iOS · 안드로이드)

> 출시 순서, 계정 요건(개인사업자 위험), 스토어 문구, 개인정보 라벨은
> [docs/store-release.md](docs/store-release.md) 와 [docs/store-listing.md](docs/store-listing.md) 에 있습니다.

같은 화면을 [Capacitor](https://capacitorjs.com) 로 감싸 앱으로 만듭니다. 앱 안에는 화면 파일(`dist-app`)이
들어 있고, 분석·계정 API 는 배포한 서버를 부릅니다.

```bash
npm run build:app          # 앱용 화면 빌드 (기본 API 주소: https://nailsense.fly.dev)
APP_API_BASE=https://내서버 npm run build:app   # 다른 서버를 쓸 때 (https 만)
npx cap sync               # android/ · ios/ 프로젝트에 화면과 플러그인 반영
npm run check:app          # 앱 방식(다른 출처 + 토큰 로그인) 점검
```

**웹과 다른 점**

| | 웹 | 앱 |
|---|---|---|
| 로그인 유지 | httpOnly 쿠키 | 세션 토큰을 iOS 키체인 · 안드로이드 키스토어에 보관, `Authorization: Bearer` 로 전송 |
| 출처 | 서버와 같음 | `capacitor://localhost`(iOS), `https://localhost`(안드로이드). 서버가 이 출처만 CORS 로 허락 (`APP_ORIGINS` 로 변경) |
| 무료 한도의 기기 구분 | `ns_device` 쿠키 | 설치할 때 만든 무작위 아이디(`X-NailSense-Device`) + IP 한도 |

- 앱은 쿠키 전송을 허락받지 않으므로(`Access-Control-Allow-Credentials` 없음), 앱 출처를 흉내 내도 웹 세션은 못 씁니다.
- 앱 전용 코드(보안 저장소)는 웹 빌드에 들어가지 않습니다.
- 안드로이드는 카메라 권한을 요청하지 않습니다(시스템 카메라 앱으로 찍음). 기록·사진이 기기 백업으로 나가지 않게 `allowBackup` 을 껐습니다.
- iOS 는 카메라 · 사진 보관함 사용 이유 문구와 영어 · 한국어 지원(`CFBundleLocalizations`)을 넣었습니다.

**아직 확정할 것**: 앱 아이디 `com.nailsense.app` 은 임시입니다. 스토어에 한 번 올리면 바꿀 수 없으므로
첫 업로드 전에 정해 `capacitor.config.ts`, `android/app/build.gradle`, iOS 프로젝트에서 함께 바꿉니다.

**빌드**: Mac 없이 [Codemagic](https://codemagic.io) 으로 iOS(TestFlight) · Android(Play 내부 테스트)를 만듭니다(`codemagic.yaml`).
안드로이드 출시용 서명 키는 저장소에 넣지 않고 Codemagic 에 올립니다(`CM_KEYSTORE_PATH` 등으로 넘어옴).

**아이콘 · 시작 화면**: 원본은 `assets/icon.svg` 하나. `npm run make:icons` 가 iOS(알파 채널 없는 1024px) ·
안드로이드(적응형 · 원형 · 예전 방식) 아이콘과 스플래시를 모두 다시 만듭니다.

**공개 페이지**(스토어 등록에 필요, 로그인 없이 열림): `/privacy`, `/terms`, `/delete-account`, `/support`.
앱 안 약관과 같은 원본(`shared/legal.ts`)에서 만들고, `?lang=ko` 또는 브라우저 언어로 한국어가 나옵니다.

**빌드 확인 상태**: 안드로이드 디버그 APK 와 서명 전 출시용 번들(aab)은 이 저장소에서 빌드되는 것까지
확인했습니다(실기기 · 에뮬레이터 실행은 아직). iOS 는 Mac 이 없어 여기서 빌드하지 못했고, Codemagic 설정은
문법만 확인했습니다(실제 클라우드 빌드는 계정 연결 뒤에 가능).

## 분석 프로바이더

**Gemini** 와 **Claude** 를 모두 지원합니다. 키가 설정된 쪽이 자동으로 선택되고,
둘 다 있으면 Gemini 를 씁니다. `ANALYSIS_PROVIDER=gemini|claude` 로 명시할 수 있으며,
어느 쪽이 쓰이는지는 서버 기동 로그에 찍힙니다.

두 프로바이더는 **같은 시스템 프롬프트와 같은 출력 스키마**를 씁니다.
프로바이더를 바꿔도 진단 금지 규칙과 화면이 받는 데이터 모양이 달라지지 않습니다.

| | Gemini | Claude |
|---|---|---|
| 환경변수 | `GEMINI_API_KEY` | `ANTHROPIC_API_KEY` |
| 기본 모델 | `gemini-3.8-flash` (`GEMINI_MODEL`) | `claude-opus-5` (`ANTHROPIC_MODEL`) |
| 구조화 출력 | `responseJsonSchema` + `responseMimeType` | `output_config.format` |
| 키 전달 | `x-goog-api-key` 헤더 | `x-api-key` 헤더 |

- 응답은 스키마를 걸어 받은 뒤에도 **서버에서 zod 로 한 번 더 검증**합니다.
  바깥에서 온 문자열을 그대로 믿지 않습니다.
- 모델이 6개 항목을 빠뜨리거나 순서를 바꿔도 서버에서 보정합니다.
- 안전 정책으로 거절되거나(`declined`), 응답이 잘리거나, 형식이 어긋나면
  각각 구분된 오류로 사용자에게 안내합니다.
- Claude 쪽은 정책 거절 시 같은 호출 안에서 대체 모델로 재시도합니다
  (`fallbacks: "default"`).

## 디자인

관찰 기록장처럼 차분하게 읽히는 화면을 목표로 합니다. 모든 값은 `web/src/styles.css` 맨 위의
토큰에서 정하고, 컴포넌트는 토큰만 읽습니다.

- **색**: 푸른 기가 도는 흰 바탕, 잉크색 글자, 강조색은 코발트 하나. 초록·호박·주황·빨강은
  "얼마나 신경 쓸지"를 나타낼 때만 쓰고, 언제나 글자와 아이콘 모양(체크, 눈, 청진기, 느낌표)이
  함께 붙어 색만으로 구분하지 않습니다. 글자 대비는 라이트·다크 모두 WCAG AA 이상입니다.
- **다크 모드**: 기기 설정(`prefers-color-scheme`)을 따릅니다. `data-theme="light|dark"` 를
  루트에 붙이면 그쪽이 우선합니다.
- **글꼴**: IBM Plex Sans(본문), IBM Plex Mono(관찰 지표 같은 수치). 직접 호스팅하며
  문자 범위(라틴, 라틴 확장 등)별로 나뉘어 화면에 나온 범위만 내려받습니다(`web/src/fonts.ts`).
  서버 없는 단일 HTML 데모만 Google Fonts 에서 같은 글꼴을 불러옵니다.
- **아이콘**: Phosphor 한 가족만 씁니다. 화면 코드는 `web/src/components/Icons.tsx` 의 별칭만 씁니다.
- **모서리**: 버튼·입력칸·칩·사진·묶음·시트는 10px, 작은 태그는 6px. 원형은 스위치뿐입니다.
- **카드**: 특이 사항처럼 한 덩어리로 읽어야 하는 것에만 테두리를 두고, 나머지는 간격과 가는
  구분선으로 묶습니다. 관찰 지표는 건강 점수로 읽히지 않도록 링이나 막대 없이 숫자로만 적습니다.
- **움직임**: 눌렀을 때의 반응, 시트 열림, 항목 펼침, 분석 중 자리 표시만 움직입니다.
  `prefers-reduced-motion` 이면 모두 멈춥니다.
- **문구**: 줄표(—, –)를 쓰지 않습니다. 분석 결과에 섞여 오면 서버가 쉼표로, 숫자 범위는
  하이픈("2-3 weeks")으로 바꿉니다
  (`server/analysis-core.ts` 의 `tidyDashes`).
